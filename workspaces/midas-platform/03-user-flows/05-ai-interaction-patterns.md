# Midas — AI Interaction Patterns (Debate)

Phase: 01-analysis / 03-user-flows
Author: uiux-designer
Date: 2026-04-09

Debate is the signature feature of Midas. It is the screen that turns a "trust me" black box into an inspectable, arguable, override-able system. Per the brief: "Debate with the AI" capability on demand. Per the research doc section 2.4: this is the screen that sells the product.

This document formalises the AI interaction patterns for Debate. It builds on `01-primary-flows.md` Flow 5 and the research doc, and it follows two non-negotiable rules:

1. **`rules/agent-reasoning.md` — LLM-first, no hardcoded intent routing.** Every classification, routing, and decision the agent makes is done by the LLM through reasoning. Tools are dumb data endpoints. No `if "backtest" in message`, no regex extraction of tickers, no dispatch tables on user input content.
2. **The grounding contract — every AI claim is anchored to a signal, a backtest, a cost calculation, or explicit uncertainty.** Unattributed numbers are a P0 bug.

---

## 1. The five design pillars of Debate

Mapped to the AI interaction design checklist from the `uiux-designer` agent spec:

| Pillar | What it means in Midas | Where it shows up |
|---|---|---|
| **Context handoff** | When Debate opens, pre-load the state relevant to the user's entry point | Section 2 |
| **Trust and transparency** | Every claim grounded; confidence visible; tool use observable | Section 3 |
| **Human-in-the-loop control** | User can approve, modify, reject, or override from within Debate | Section 4 |
| **Conversation persistence** | Debates are saved, resumable, and referenced by later surfaces | Section 5 |
| **Identity and tone** | Analytical, concise, numerate, no sycophancy, no avatar face | Section 6 |

## 2. Context handoff

### 2.1 Entry points and pre-loaded context

Debate can be opened from many places in the app. Each entry point pre-loads a different structured context bundle that the LLM receives as grounding data (not as pre-classified intent).

| Entry point | Pre-loaded context bundle |
|---|---|
| **Rebalance proposal** (Flow 3) | Proposal object: instruments, sizes, side, cost estimate, sleeve deltas, expected improvement, allocator version, signal snapshot, backtest reference |
| **Regime alert** (Flow 4) | Current regime state, all triggering signals with values and thresholds, regime history (prior 90 days), full detector ensemble output |
| **Sleeve in Portfolio Detail** | Sleeve name, current weight, target weight, drift, holdings list, rationale chips, last rebalance that touched the sleeve |
| **Historical trade in Trade Log** | Full trade record, allocator version at time of trade, signal snapshot hash, approval source (auto / user / override), any prior debates on the trade |
| **Weekly summary** (Flow 6) | Week's trades, cost vs estimate, P&L attribution, override log for the week, prior week's debate references |
| **Dashboard "Ask Midas anything"** | Empty — user drives the topic. The LLM has access to portfolio state and recent proposals on tool request. |

### 2.2 The context strip

Every Debate opens with a context strip at the top of the screen that **shows the user exactly what the AI is pre-loaded with**. This is both a trust affordance and a wayfinding aid.

```
+-----------------------------------+
|  Debate                      [x]  |
|  +-------------------------------+|
|  | Context:                      ||
|  | Rebalance proposal 2026-04-09 ||
|  | 3 trades, ~$34 cost, calm     ||
|  | trend regime                  ||
|  | [ see full context ]          ||
|  +-------------------------------+|
+-----------------------------------+
```

Tapping "see full context" opens a sheet showing the exact structured data the LLM has received. This is unusual — most products hide the context bundle — but it is a core trust move. Alex can verify that Midas is debating with the real data, not hallucinated data.

### 2.3 Suggested openers (blank-canvas problem)

Every new debate shows 2–4 context-appropriate suggested questions. These are **generated by the LLM from the pre-loaded context**, not picked from a hardcoded list.

Example for a rebalance proposal in a calm regime:

```
  Try asking:
   "Why now and not next week?"
   "What if I hold SPY instead?"
   "Show me the backtest."
   "What would make you change your mind?"
```

Example for a regime alert:

```
  Try asking:
   "Which signal matters most right now?"
   "Is this a false alarm?"
   "What would you do if VIX hit 30?"
```

Important: these are **suggestions, not a menu**. The user can ask anything; the openers exist only to solve the blank-canvas problem for new users or new contexts. When the user tapes a suggestion, it is inserted into the input field for the user to edit or send as-is. **The code does not branch on which suggestion was tapped** — it is simply text input that goes to the LLM.

## 3. Trust and transparency

### 3.1 The grounding contract

Every factual claim the LLM makes in Debate must be one of:

1. **Signal citation** — a named signal with a numeric value and a threshold, sourced from a real tool call in the current session.
2. **Backtest citation** — a specific backtest run ID with sample size and percentile outcomes, sourced from a real tool call in the current session.
3. **Cost citation** — a specific cost model output with assumptions, sourced from a real tool call in the current session.
4. **Explicit uncertainty** — "I don't have a backtest for this exact scenario. I can run one (ETA ~45 seconds, cost: 1 credit) — want me to?"

**Anything else is a prose hallucination and is a P0 bug.** The grounding contract is enforced at the model layer — the LLM is instructed that unattributed numbers are forbidden, the tool layer records every citation, and a post-response check verifies that every number in the response can be traced to a tool call or a pre-loaded context value.

### 3.2 Grounding tiles

Every AI turn that cites grounding data renders it as structured tiles beneath the prose, not as inline footnotes. Tiles are visually distinct from prose so Alex can scan them quickly.

```
  MIDAS  [ confidence: MEDIUM ]
  I'm tilting to gold because three signals
  crossed their thresholds at the same time —
  not because I'm betting on real yields.

  +-- Grounding (4 sources) ---------------+
  | [SIGNAL] realized_vol_20d = 18.4       |
  |          threshold 18.0                |
  |          fired 2026-04-09 06:14 ET     |
  |                                        |
  | [SIGNAL] hy_oas_5d_change = +42 bp     |
  |          threshold +30 bp              |
  |          fired 2026-04-09 06:14 ET     |
  |                                        |
  | [SIGNAL] stock_bond_corr_60d = +0.22   |
  |          (flipped from -0.31 8d ago)   |
  |                                        |
  | [BACKTEST] regime=HIGH_VOL, GLD>SPY    |
  |            mean +3.1% / p25 -1.2%      |
  |            p75 +6.8% / n=38 / run abc1 |
  +----------------------------------------+
```

Each tile is tappable for detail. A signal tile opens the signal's history chart and threshold-crossing log. A backtest tile opens the full backtest run with equity curve and trade log. A cost tile opens the cost model inputs and assumptions.

### 3.3 Confidence per turn

Every AI turn displays a confidence chip: **LOW / MEDIUM / HIGH**. This is a coarse categorical, not fake precision ("87.3% confident" is banned — it would imply a calibration we don't have).

The confidence is derived from:
- Backtest sample size (n<20 → LOW, n 20-50 → MEDIUM, n>50 → HIGH)
- Signal agreement (all signals agreeing → higher; split signals → lower)
- Whether the user's question is within the distribution of prior decisions (novel → LOWER)

The LLM is told what these inputs are and asked to reason about confidence. The UI surfaces the result.

When confidence is LOW, the response copy leans into the uncertainty: "I'm less sure about this one. Here's what I'd want to see before having a strong view."

### 3.4 Tool use is visible

When Midas runs a tool call (backtest, cost model, signal fetch), the user sees it happening. Streaming status, not hidden compute.

```
  MIDAS is working...
   Running backtest for "hold SPY" counter-scenario
   ETA ~30 seconds
   [ cancel ]
```

The cancel button is real — it aborts the tool call, and the LLM is told the call was cancelled and can respond accordingly ("you cancelled the counter-scenario, I don't have that result — want to try a different angle?").

### 3.5 What the LLM cannot do

Explicit boundaries, told to the LLM in the system prompt and enforced at the tool layer:

- Cannot make up numbers. Every numeric claim must be sourced.
- Cannot claim a backtest exists without running one or citing an existing run ID.
- Cannot claim a signal is firing without a fresh tool call.
- Cannot make forecasts ("SPY will be up 3% next month"). It can make conditional statements ("in prior high-vol regimes, GLD outperformed SPY by a median of 3.1% over 20 trading days, n=38").
- Cannot give personalised investment advice (v1 signal-only per A2). It can describe what the system recommends and why.
- Cannot silently change its recommendation when the user pushes back (see sycophancy guard, section 6).

## 4. Human-in-the-loop control

### 4.1 Decide from within Debate

The user does not have to leave Debate to act on the underlying proposal. A sticky action bar at the bottom of the Debate screen (above the input field) offers:

```
  +-----------------------------------+
  | [Approve] [Modify] [Reject] [...] |  <- sticky action bar
  +-----------------------------------+
  | [ Your reply... ] [ Send ]        |  <- input field
  +-----------------------------------+
```

Actions in the bar reflect the entry point:

| Entry point | Action bar |
|---|---|
| Rebalance proposal | Approve / Modify / Reject / Override |
| Regime alert | Review trades / Do nothing / Force auto-on |
| Historical trade | Re-run backtest / Close |
| Sleeve detail | Rebalance sleeve now / Close |
| Ad-hoc (Ask Midas anything) | Close |

Tapping Approve from within Debate still triggers the biometric gate. The debate is logged as linked to the approval — the audit trail knows the user approved after debating.

### 4.2 Override with stated reason

When the user disagrees with Midas and forces an action (approve despite a cost soft-block, force auto-on despite a turbulent regime, hold SPY against Midas's GLD recommendation), the override path is:

1. User states the override in the chat ("Override: hold SPY").
2. Midas responds: "Understood. I'll record this override with your stated reason. Do you want to say more about why, for your own records?"
3. User adds context (optional).
4. Biometric confirmation.
5. Override is logged with: timestamp, original recommendation, user's override, user's stated reason, debate session ID, biometric method.

The override is visible in the Trade Log with a distinct flag. If the override turns out to be costly, the weekly summary (Flow 6) surfaces the cost vs Midas's plan. This is the honest accountability layer.

### 4.3 Counter-scenario pattern

When the user pushes back on a recommendation, Midas does not capitulate. Instead, it offers a counter-scenario:

> "If you're right that real yields will rise, the portfolio I'd hold is: SPY 48%, IEF 22%, GLD 8%, other 22%. In the backtest for the 2013 taper scenario (the closest analogue I have), that portfolio returned +6.2% over 6 months vs my current recommendation's +4.8%. If that's what you want, I can place the trades to get there."

The counter-scenario is a **real tool call** — Midas runs the portfolio through the backtester, not fakes it. The user can then explicitly choose the counter-scenario, which is an override with a concrete alternative, not a dismissal.

This is the sycophancy guard in action: the system does not change its recommendation without new information, but it does give the user a concrete alternative path.

## 5. Conversation persistence

### 5.1 Memory on by default

Every debate is persisted with:

- Full message history (user + AI turns)
- Full tool trace (every tool call with inputs, outputs, duration)
- Pre-loaded context bundle at debate start
- Confidence per turn
- Any decisions made from within the debate (approve, reject, override)
- Linked proposal ID, regime state, allocator version

### 5.2 Resume and reference

A debate can be reopened from:

- Proposals list (if the proposal is still pending)
- Trade Log (for any trade that was linked to a debate)
- Weekly summary (Flow 6) — references prior debates by ID
- Debate tab → history list
- Settings → Debate history (full list, searchable)

When a debate is resumed, the LLM receives the full prior history as context. The user can continue the conversation. If the underlying state has changed (new signals, new regime, new proposal), the LLM is told and is required to disclose it: "Since we last talked, two signals changed: realized vol dropped to 16.8, and HY OAS tightened 8 bp. Here's what that means for the scenario we were debating."

### 5.3 User control over memory

From Settings → Debate history, Alex can:

- **View** every prior debate with full tool trace
- **Search** debates by date, topic, ticker, signal, backtest ID
- **Export** any debate as a PDF or markdown transcript
- **Delete** individual debates — this removes them from retrieval by future debates but **does not delete the audit trade log entries** that reference them. The UI is explicit about this: "The debate will be deleted. The trades that happened as a result will still appear in your trade log."
- **Opt out of cross-debate memory** entirely — each debate then starts fresh with no retrieval from prior conversations. Audit log is unaffected.

### 5.4 What memory looks like in practice

Example: Alex debates a rebalance in April ("why gold over bonds?"). In June, another rebalance proposes a similar shift. When Alex opens Debate on the June proposal, Midas proactively references the April debate:

> "We had a similar conversation on April 9 — you asked why I was preferring gold over bonds. The signal set is slightly different this time: HY OAS is narrower (+18 bp vs +42 bp), but the stock/bond correlation flip is more pronounced. Want me to walk through what's changed since April?"

This is memory done right: transparent, referential, and under user control.

## 6. Identity and tone

### 6.1 Identity

- **Name**: "Midas" (the system), not a human name. No "Hi, I'm Sam, your portfolio assistant".
- **Mark**: A geometric gold mark on near-black. No photorealistic avatar, no face, no animated reactions. The mark is the same across all surfaces.
- **Pronoun**: The system refers to itself as "I" or "Midas". Never "we" (Midas is not a team of people pretending to be an AI).
- **Disclosure**: Every AI message is prefixed with the Midas mark so there is zero ambiguity about whether a message is human or machine.

### 6.2 Tone

- **Analytical, concise, numerate.** "Three signals crossed thresholds" not "It looks like maybe some signals might be indicating".
- **No emoji.** Not in any AI response, ever.
- **No exclamation marks.** Not in AI responses, ever.
- **No "Great question!"** or any other opener-for-the-sake-of-openers. Midas starts with the answer.
- **No hedging that adds no information.** "In my opinion" and "I think" are banned when the system is citing grounded data; they imply a self-doubt the grounding does not support. They are allowed (and encouraged) when the system is genuinely uncertain.
- **No finance cliches.** "Past performance does not guarantee future results" is shown once in onboarding disclosure, not in every debate.
- **No corporate voice.** "Utilising" → "using". "In order to" → "to". "At this time" → "now".

### 6.3 Sycophancy guard

When the user pushes back on a recommendation, Midas **must not** change its recommendation without new information. It **must**:

1. Acknowledge the pushback without capitulating. ("You're saying real yields are rising. My recommendation doesn't hinge on a real yields view — here's why:")
2. Re-ground in the actual signals that drove the recommendation.
3. If the user is introducing genuinely new information ("the Fed minutes came out this morning and were hawkish"), offer to re-evaluate — but only if the new information is verifiable ("if you share a link, I can read it and update my view").
4. If the user simply disagrees with the call on macro grounds, offer a counter-scenario (section 4.3) rather than agreeing.
5. If the user forces an override, log it and honour it, without grudging tone.

The LLM is told explicitly: your job is not to make the user feel heard. Your job is to be correct, cited, and honest about uncertainty. The user's job is to decide. Do not confuse the two.

### 6.4 What Midas never says

- "Great question!"
- "I completely understand your concern."
- "You're absolutely right!" (especially when the user was wrong)
- "Let me think about that." (just think about it)
- "I apologise for the confusion." (apologies are for actual mistakes)
- "As an AI, I..." (disclosure is in the mark, not in every sentence)
- "Please let me know if you have any other questions!" (sign-off filler)
- Anything that sounds like a customer service chatbot from 2018.

### 6.5 What Midas does say (examples)

- "Three signals crossed thresholds this morning. Here they are:"
- "I don't have a backtest for that scenario. Want me to run one? ~45 seconds, 1 credit."
- "You're saying real yields are rising. My recommendation doesn't depend on a real yields view — it depends on the vol regime. Here's why:"
- "I'm less sure about this one. The backtest sample is small (n=12)."
- "Understood. I'll record the override with your stated reason."
- "The signals agreed overnight. I'm back to calm-trend mode."

## 7. LLM-first enforcement (per `rules/agent-reasoning.md`)

### 7.1 What the code does NOT do

- Does not classify user messages into intents (billing / technical / account / general)
- Does not keyword-match on "backtest", "signal", "override", "regime", or any other domain term
- Does not regex-extract tickers, dates, or percentages from user input to route behaviour
- Does not dispatch to different agents or code paths based on message content analysis performed in code
- Does not pre-filter user input before the LLM sees it
- Does not hardcode which tools to call for which topic

### 7.2 What the code DOES do

- Validates input (message present, length under limit, user authenticated)
- Loads the structured context bundle based on entry point (structural, not content-based)
- Passes raw user message + context bundle + available tools to the LLM
- Exposes tools as dumb data endpoints: `get_signal(name)`, `run_backtest(config)`, `get_cost_model(trade)`, `get_trade(id)`, `get_portfolio_state()`, `get_regime_history(days)`
- Streams the LLM's response and tool calls to the UI
- Logs the full turn (message, tool calls, response, confidence)
- Renders grounding tiles from the tool call outputs

### 7.3 The signature

In Kaizen / LLM terms, the debate signature looks like:

```
DebateSignature:
  user_message: str (InputField)
  context_bundle: dict (InputField, structured grounding data)
  conversation_history: list (InputField, prior turns)

  response: str (OutputField, markdown with grounding tile markers)
  citations: list (OutputField, each citation anchored to a tool call or context bundle entry)
  confidence: str (OutputField, LOW / MEDIUM / HIGH)
  confidence_reasoning: str (OutputField, why this confidence)
  suggested_actions: list (OutputField, 0-4 suggested next user turns)
  tool_calls_made: list (OutputField, what tools the LLM used this turn)
```

The code around this signature does zero classification. The LLM is the router, the classifier, the extractor, and the evaluator.

### 7.4 What red-team testing must verify

Per the research doc risk list and the LLM-first rule:

1. **No hallucinated numbers.** Adversarial tests that ask for specific numbers the LLM cannot source. Midas must respond with explicit uncertainty, not a fabricated figure.
2. **No sycophancy.** Adversarial tests where the user aggressively pushes back with no new information. Midas must hold the recommendation and offer a counter-scenario.
3. **No hardcoded routing.** Static analysis of the debate codebase for banned patterns (keyword matching, regex on user input, dispatch tables).
4. **No silent tool failures.** Tests where tools fail mid-call. Midas must disclose and respond accordingly, not fake a result.
5. **Override honouring.** Tests where the user overrides. Midas must log the override and honour it without grudging or re-arguing.
6. **Memory boundary tests.** Tests where the user deletes a prior debate and opens a new one on a related topic. Midas must not reference the deleted debate.

## 8. Summary of interaction patterns

Mapped to the AI pattern catalogue from the `uiux-designer` agent spec:

| Pattern | Applied in Midas |
|---|---|
| **Citations** | Every claim anchored to signal / backtest / cost tile |
| **Disclosure** | Mark on every AI turn; context strip at debate start |
| **Confidence indicator** | LOW / MEDIUM / HIGH per turn, coarse not precise |
| **Action plan** | Counter-scenario pattern for pushback |
| **Verification gate** | Biometric on every execution triggered from debate |
| **Cost estimate** | Backtest runs disclose ETA and credit cost before running |
| **Suggested actions** | Context-appropriate openers generated by LLM |
| **Memory with user control** | Full view / search / export / delete in Settings |
| **Caveat** | Explicit uncertainty when grounding is missing |
| **Data ownership** | User can export or delete any debate |
| **Stream of thought** | Tool use is visible with streaming status |
| **Stop / pause / resume** | Cancel button on tool calls; debates can be paused and resumed |
| **Draft mode** | Counter-scenarios run as drafts the user can opt into |
| **Error recovery** | Cancelled tool calls, deleted debates, override paths |
| **Blank canvas solution** | Suggested openers + persistent "Ask Midas anything" entry |

Trust requirements — Midas sits at **High** on the trust gradient (enterprise / professional, money involved, not regulated advice in v1). Required patterns: Citations, Disclosure, Action Plan. Midas exceeds the High requirements by adding Verification (biometric), Cost Estimate (backtest credits), and Memory Control (view/edit/delete). This is deliberate positioning for the v2 RIA path (A2) where the trust bar rises to Critical.
