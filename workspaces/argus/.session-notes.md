## Key Findings

### Critical: IBKR OAuth Scopes (HIGH)
Midas requests `place_order` scope. Argus needs only `read_positions`. Scope string change + new constructor param. Isolated fix, no dependencies.

### Critical: Data Model Mismatch (HIGH)
- `signals` table has NO `user_id` (publisher exemption, ADR-001)
- No `guidelines` or `violation_records` table — must build from scratch
- `Position` dataclass missing sector/asset_class/is_leveraged fields

### Critical: Approval vs Violation Workflow (HIGH)
`ApprovalHandlers` tightly coupled to `signals` JOIN. Must write new `ViolationHandlers` from scratch. Status machine is similar but domain is different enough to justify separate classes.

### ML: Use Case Drives Method (ML specialist)
- "Find similar ETFs" is underspecified — the question determines the algorithm
- The sleeve taxonomy (10 sleeves, 23 ETFs) IS the clustering prior — K-means can validate it, not just discover it
- "10 features" don't exist as persisted data — feature store required first
- **Week 9 ship**: Precision@3 diagnostic, not consumer-facing similarity
- **Precision@3**: for each ETF, find 3 nearest neighbors; count how many share the same sleeve ID

### Architecture Decision: Threshold-Based Rule Engine
Week 9 ships threshold-based rule evaluation (no ML, no LLM). NLP parsing deferred. When added, it generates structured Guideline records — same engine evaluates them.
